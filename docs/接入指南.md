# 接入指南

## Kotlin 与 Android

公共包沿用 `com.dgtang.live.data.local`。`NativeStorageModule.read` 返回 `NativeStorageRead(successful, value)`：成功且 null 仅表示 Key 不存在；失败不能作为首次初始化信号。`KeyValueStore.getString` 保持旧合同，缺失映射为空字符串；需要区分存储失败时使用 `TypedKeyValueStore.read`。

Android 在应用级创建 `AndroidMmkvStorage(context)`；它使用官方 `MMKV.initialize(context.applicationContext)` 默认目录。不可在升级时改 StoreID、目录或用 `encodeString` 替代 UTF-8 bytes。每一 StoreID 只装配一个 `NativeKeyValueStore`，跨实例/跨进程不提供共同的 Kotlin 原子锁。

## iOS

通过 Git 精确 native tag 接入 CocoaPods（未发布到 Specs）：

```ruby
pod 'GycStorage', :git => 'https://github.com/gycrosskit/storage.git', :tag => 'native-0.1.0-rc.1'
```

SPM 使用本仓精确版本 `0.1.0-rc.1` 的 `GycStorage` 产品。组件不导入宿主 `Shared`。宿主明确传入旧目录：

```swift
let documents = FileManager.default.urls(for: .documentDirectory, in: .userDomainMask)[0]
let driver = GycMmkvStorage(rootDirectory: documents.appendingPathComponent("mmkv").path)
```

在宿主自己的 `Shared.NativeStorageModule` adapter 内，逐方法转发 write/remove/removeAllExcept/clear。读取映射为：

```swift
let result = driver.read(storeId: storeId, key: key)
return Shared.NativeStorageRead(successful: result.successful, value: result.value)
```

组件公开结果名为 `GycStorageRead`，不与 Shared 的类型混淆。驱动和 adapter 为应用级单实例，页面释放不关闭 MMKV。SDK 缓存受 NSLock 保护，Kotlin 的同 Store 写锁仍由 `NativeKeyValueStore` 持有。

## OHOS

```typescript
import { NativeMmkvStorage } from '@gycrosskit/storage-native';
const storage = new NativeMmkvStorage();
storage.initialize(context.filesDir + '/mmkv', context.cacheDir);
native.installStorageModule((request: string): string => storage.invoke(request));
```

应用持有该实例，在任何后台 Kotlin 调用/Renderer 创建前初始化。原生 JSON 协议保持 operation/storeId/key/value/keys，失败返回 `{"ok":false}`，读取缺失返回 `{"ok":true,"value":null}`；不记录原始 Key、值或异常。StoreID 只接受 `[a-z][a-z0-9_]*`。

HAR 携带 `src/main/resources/rawfile/native/gyc_storage_bridge.h`。宿主在解包后的真实 OHPM 包目录核对该文件，并将其目录加入 NAPI target 的 include 路径；启用 C++17。参考 [CMake 样例](../verification-ohos/storage_bridge.cmake)。若 HAR 工具改变目录布局应先适配准确路径，不得回落到旧宿主桥实现。

```cpp
#include "gyc_storage_bridge.h"
extern "C" void host_install_storage_dispatcher(GycStorageDispatcher);
napi_value InstallStorageModule(napi_env env, napi_callback_info info) {
    return GycStorageInstall(env, info, host_install_storage_dispatcher);
}
```

`host_install_storage_dispatcher` 为宿主已有 Kotlin `@CName` 安装函数，宿主自行决定导出名；组件不依赖该符号。它接收 `char* (*)(const char*)`，然后调用 `OhosNativeStorageModule.install(pointer)`。JSON 输出使用 malloc 兼容内存，Kotlin 在解析的 finally 中 free。主 ArkTS 线程直接调用 handler，后台线程通过应用级 TSFN 回到 ArkTS 后同步等待；不能由 ArkTS 主线程阻塞等待发起该请求的后台任务。此桥为进程级、安装一次，无页面 dispose。

## 升级检查

先保留原 MMKV 数据，固定 StoreID、目录和 UTF-8 bytes。`removeAllExcept` 只删除未保留 Key，不先 clear 再恢复。账号清理与白名单由业务宿主决定；组件不迁移业务字段，不主动清空历史数据。原生包/Maven 制品分别验收后，宿主再删除原实现，编译通过不能代替真机数据升级验收。
