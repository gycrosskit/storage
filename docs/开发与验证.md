# 开发与验证

## 轻量检查

```sh
node --test verification/native-mmkv-storage.test.cjs verification/storage-native-bridge.test.cjs
bash verification/ios/run.sh
ruby -c GycStorage.podspec
swift package dump-package
bash -n scripts/archive-prebuilt.sh jitpack-install.sh
git diff --check
```

Node 需要 TypeScript（可用 `TYPESCRIPT_PATH` 指定模块绝对路径）与当前 Node 的开发头文件；原生桥由 clang++ 真实编译。Swift 轻量脚本编译实际组件源码，但 MMKV 为 [替身](../verification/ios/MMKV.swift)。它只验证组件 API/编码/失败语义，不代表官方 SDK 链接。探针使用独立临时目录，不接触业务数据。

## 受管 SDK 与消费

按 GY CrossKit 的统一 `ci.py component-run` 入口运行；本仓不提供绕过该入口的 SDK 调度。目标是：storage-core JVM 行为测试、storage-mmkv Android 编译和 targeted unit test、core 三端编译、官方 MMKV iOS 链接/运行、HAR 构建、独立三端消费。每个目标的用例数、失败、跳过和缓存分别记录。

- Maven consumer：[verification-consumer](../verification-consumer/build.gradle.kts)，默认仅 JitPack 精确版本；候选验证通过 `storageRepository` 指定本轮独立产物目录，不使用源码 substitution/mavenLocal。
- Swift consumer：[verification-ios](../verification-ios/Package.swift)，消费真实 `GycStorage` 产品，官方 MMKV 固定 2.4.3。上游 manifest 要求 Swift 6.2；须核对当前工具链和远程依赖解析，不用 Pod 结果代替 SPM。
- OHOS consumer：[verification-ohos](../verification-ohos/consumer/Index.ets)，只依赖 HAR 的公开入口；解包后检查 NAPI 头文件路径，消费实际包中的头文件并执行主/后台 fixture，不能使用仓库源文件冒充 HAR 产物消费。
- 真实 iOS 数据回归可将 [NativeStorageCompatibilityMain.swift](../verification/NativeStorageCompatibilityMain.swift) 链接到官方 MMKV/GycStorage 执行，`GYC_STORAGE_TEST_ROOT` 可设专用测试目录。探针构造旧 UTF-8 bytes 后读取并验证保留值。
- [LegacyMmkvWriter.mm](../verification/LegacyMmkvWriter.mm) 是旧 KMP 二进制的可选交叉验证输入，需要原固定 Tag 的 MMKVBridge.h/libmmkv-kmp.a，必须显式指定独立 `GYC_STORAGE_TEST_ROOT`；未提供这些原件就不声称旧二进制迁移已验收。

## 发布输入

首个正式版本 `1.0.0` 已发布。Maven group `com.github.gycrosskit.storage`；publication 共 9 个：core 根、android、jvm、iosarm64、iossimulatorarm64、iosx64、ohosarm64；mmkv 根、android。`VERSION` 固定不可变版本；staging 固定 `build/maven`，归档脚本发现该路径已存在（包括链接）立即拒绝，保留旧候选与失败原件，不自动清空或复用。Java/Kotlin JVM target 固定 11，归档检查字节码上限 55。

受管 builder 使用 `VERSION=1.0.0` 调用 `scripts/archive-prebuilt.sh`，输出 `build/prebuilt/storage-maven.tar.gz` 与 SHA256SUMS，先执行共用 metadata 归一化与完整性检查。JitPack 入口只安装已公开且在 release-checksums.txt 登记摘要的相同归档。正式 `1.0.0` 摘要已登记；未登记版本仍会失败，不现编译或猜测候选。

原生 CocoaPods 使用 GycStorage.podspec，通过已发布的 Git 精确 `native-1.0.0` tag 接入，未发布到 Specs；SPM 使用 Package.swift 与已发布的精确 `1.0.0` tag，两个 tag 指向同一冻结源码 SHA。HAR 名称 StorageNative，目录 ohos/storage-native，包名 @gycrosskit/storage-native，版本 `1.0.0`、精确 tag `har-1.0.0`；[HAR Release](https://github.com/gycrosskit/storage/releases/tag/har-1.0.0)与私有 OHPM 精确版本均已发布。私库分发不代表官方 Registry 上架，渠道发布、安装与完整消费分别记录。
